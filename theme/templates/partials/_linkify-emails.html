{# _linkify-emails.html - turn a bare email address into a mailto link. QA ref 63, second round. The first fix linked addresses in ONE field of the Contact Us phone directory (`extension_text`) by splitting it on spaces, and the page still failed on production: - every other field printed an address verbatim: the department label, the directory callout, the intro, the feature cards, and the FAQ further down the same page, whose own default content says "emailing membership@weldaustralia.com.au" as plain text; - splitting on a space missed an address joined to its neighbour by a non-breaking space, a slash or a colon ("Email:membership@…"), and in the colon case linked the whole token, "mailto:Email:membership@…", which goes nowhere. So the address is matched by pattern rather than by token, and every module on the page runs its text through here. Import it; do not copy it: {% import "../../templates/partials/_linkify-emails.html" as wa_email %} {{ wa_email.text(entry.department, 'my-link-class') }} (a plain text field) {{ wa_email.html(module.intro, 'my-link-class') }} (a rich text field) The pattern carries no backslashes and no lookarounds on purpose: HubL string literals treat a backslash inconsistently, and HubSpot's regex engine (RE2) refuses lookarounds outright. `[.]` is a literal full stop. The domain must carry at least one dot followed by more characters, so a full stop ending a sentence stays outside the link.
